# Releasing FElupe Studio

The web app and the Python package `felupe_studio` are released together with one version (`app/package.json` and `python/felupe_studio/__about__.py`; `tests/test_versions.py` checks that they agree). A release is a tag `vX.Y.Z` on `main` with a GitHub release; GitHub Pages always serves `main`. The tag also publishes the Python package on [PyPI](https://pypi.org/p/felupe-studio) (`.github/workflows/release.yml`, #275).

**Once, before the first release on PyPI:** a *pending publisher* of the project `felupe-studio` on PyPI (*Your projects ▸ Publishing*, or *Account settings ▸ Publishing*): the owner `adtzlr`, the repository `felupe-studio`, the workflow `release.yml` and the environment `pypi`. Then an environment `pypi` in the settings of the repository (*Settings ▸ Environments*), optionally with the maintainer as a required reviewer. Trusted publishing needs no token.

## Checklist

### Before the tag

- [ ] The issues of the milestone are closed and CI is green on `main`.
- [ ] The version is set in `app/package.json`, `app/package-lock.json` (run `npm install` in `app/`) and `python/felupe_studio/__about__.py`.
- [ ] `CHANGELOG.md` has the section of the version with its date.
- [ ] The pinned wheels (`config.wheels` in `app/package.json`) are the versions of the golden tests (`FELUPE_VERSION` in `.github/workflows/ci.yml`).
- [ ] The CI files of a brand build the release: `FELUPE_STUDIO_VERSION` in `brands/gitlab-ci.yml` and `brands/github-actions.yml`, and the versions in `docs/deployment.md` (`tests/test_brands.py` checks that they agree, the release workflow that they are the version of the tag).

### Smoke test of the deployed page

With real Pyodide, after the deployment of `main` has finished. Use the cases in `tests/golden` (a `commands.json` and its mesh files, opened together).

- [ ] Desktop Chrome and Firefox, and one phone: the page loads, the status bar shows the versions of FElupe and the load time.
- [ ] The phone in portrait and in landscape: the layout is compact and the page does not scroll; a tap on a tab opens its commands and a command closes them; the button of the command line opens it with the keyboard; nothing lies under the notch or the home indicator.
- [ ] The results on the phone, in portrait and in landscape: the contour, *Play* and the substep are one row (in landscape beside *Model* and *Results*), and *More controls* opens the others; the toolbar of the view scrolls to *Points*; the curve is off at first, and turned on it takes the bottom of the view in portrait and its right side in landscape, without covering the model or the scalar bar.
- [ ] `bar_two_materials` (`u` and `u-p-J`): Solve shows progress, then Show results; the contours of displacement, strain and stress change with the substep; the curve matches `results.json` of the case.
- [ ] `bar_mooney_rivlin`: Solve loads tensortrax first and runs.
- [ ] `bar_cell_types` (hexahedrons and tetrahedrons in one mesh file) shows results; with the formulation of a section changed to `u-p-J`, the tetrahedrons use the MINI element.
- [ ] Every sample (File ▸ Samples…) opens, solves and shows results. *Hyperelastic block with a rigid plate*: the top face stays plane and tilts with the plate; the control points show the force at `plate` and the moment at `tilt`; Export ▸ Control points (CSV) has all substeps.
- [ ] A project file of the previous schema version (e.g. saved with the previous release) opens and is migrated; saved again, it has the current schema version.
- [ ] Archives: a sample opens as `<id>.felupe.zip`; *Save project* saves the archive (with the save dialog in Chrome, as a download in Firefox), which opens again in one step (also a folder of a project zipped by hand); *Save project as…* with the script: the unpacked folder runs with `python <name>.py`.
- [ ] Units: *Model settings* with mm and N; the forms, the browser, the curve and the scalar bar show the units.
- [ ] Face sets and pressures: on the sample *Hyperelastic block with a rigid plate*, a face set of a side face (click, *Create face set*) and a pressure on it ramped by the step; it solves, and the side face bulges in (positive) or out (negative).
- [ ] Results: the contour settings (color map, bands, range over all substeps), *Min/Max* with its labels, and playing the substeps (Space).
- [ ] Picking: a click on a face creates a point set of its plane; a second click on the surface excludes it, a third one deselects it, also by taps on a phone or a tablet; with Nodes shown, Shift+click picks nodes and a click on a picked node deselects it; on a phone, a long press picks a single face (a ring shows it) and adds a node; *Control point at center* creates a control point.
- [ ] Parameters and mesh scripts: *Sandwich spring with parameters* asks for its parameters when it opens; with 5 layers instead of 3 it opens with the higher stack and is softer; *Show* reads the script; *All parameters…* changes them later. An error in a mesh script (e.g. a wrong name) is an issue of the mesh with its traceback.
- [ ] Expressions of parameters: in the sandwich spring, the step `shearing` shows `2 * cells` (*= 8*) and `0.5 * layers * height` (*End 1 = 12 mm*); with 5 layers the shear is 20 mm, with about the same force. A typo, e.g. `0.5 * layer * height`, is an issue at the field; the script shows the expressions as written. Renaming the parameter `height` renames it in the expression.
- [ ] 2D models: *Axisymmetric sandwich spring* and *Plate with a hole in plane strain* open onto the xy-plane, solve, and show their results in 2D; the plate shows the concentration of the stress at the hole.
- [ ] Contact: *Hyperelastic spring with end stops* solves; the point set `outer` highlights the surface, the contact `lower_stop` its points and its plane; in the results the plates move with their reference points and the force rises steeply at the end of the compression.
- [ ] Strain-based materials: the Materials tab has the menus *Linear elasticity*, *Hyperelasticity* and *Strain-based elasticity*. The golden case `plasticity_cube` (steel pulled beyond its yield stress and unloaded) solves; its curve matches `results.json`, the force goes back to zero at a remaining strain, and the contour *Equivalent plastic strain* is above zero. With the framework *Seth-Hill* the form asks for the *Strain exponent m*.
- [ ] Values at the points: on *Plate with a hole in plane strain*, the contour settings ▸ *Values at* ▸ *Points: projected* gives a smooth contour with a larger peak at the hole than *Cells*; the VTU of the substep has the stresses as point data.
- [ ] Samples of v0.5: *Engine mount (FElupe ex07)* solves its two jobs; the curve of `horizontal` is Fx over ux, there and back. *Metacone (FElupe ex15)* asks for its parameters and solves; the force is about -517 N at the end. *Elastic-plastic plate with a hole*: the curve unloads elastically and crosses zero force at about 0.054 mm; the contour *Equivalent plastic strain* is largest at the hole.
- [ ] Export mesh: the menu of a mesh in the browser ▸ *Export mesh…* writes a VTU that opens in ParaView, also of a mesh script with the current parameters.
- [ ] Live results: *Show live results* during a run shows the growing curve and the scenes; *Live results* off shows the curve only.
- [ ] Cancel a running job: Python loads again and Solve works again without opening the files again.
- [ ] A failing job (a large ramp with few substeps) shows the traceback; with cutback it runs.
- [ ] Exports: the Python script runs next to the mesh files with FElupe; the XDMF and the VTU open in ParaView; the PNG shows the view with its scalar bar.
- [ ] Reload: Pyodide and the wheels come from the cache (faster start).
- [ ] Bytecode cache: `spike.html` twice on a phone; the second load says *Bytecode cache: hit*, and its FElupe step is about half of the first (`docs/benchmarks.md`).
- [ ] Single precision: *Precision: Single* of the solver of a job (e.g. *Bar of two materials*) gives the curve of double precision. *Precision: Single* of the *Model settings*: the material test solves with a note *round-off … % of the reaction forces*; the sandwich spring warns (*may be 43 %*). `spike.html` runs the three precisions with the same force.
- [ ] Mesh tools: *Bushing made with mesh tools* asks for its parameters and opens; the browser shows `soft_mesh` with `runouts`, `section` and the lines below it, hidden in the viewport, and *Show* draws a construction mesh in gray. With *cells_around* 24 the meshes are made again; it solves with the curve of *Bushing with steel sleeves*. *Primitives ▸ Cube* with an expression of a parameter, *Operations ▸ Expand* of it is an issue (*expand needs a mesh of vertex, line or quad cells*); selecting a mesh shows its line in the script. *Export mesh…* of `soft_mesh` writes a VTU.
- [ ] Load cycles and the Mullins effect: *Bushing with the Mullins effect* opens; the browser shows `filled_rubber` as *Neo-Hooke · Mullins* and the steps of the job in their order, `load` twice. It solves: the unloading needs less force than the first loading, the second loading follows it back and meets the first loading at 6 mm; the contour *Max. strain energy density* (group *Mullins effect*) stays when the bushing is unloaded. *+ Add step* of a job adds a step, also one that is already in it, and × removes one. The tutorial *A load cycle with the Mullins effect* of the guide gives the forces it names.
- [ ] Derived parameters: in the sandwich spring, a parameter `total` with the value `sheet + layers * (height + sheet)` shows *32 mm = sheet + layers * (height + sheet)* in the browser and below the others in the dialog of the parameters, and follows a changed `layers` there; two parameters that use each other are an issue (*… depends on itself through …*); the script defines `total` after the others.
- [ ] Colors and constraints: *Color* of a mesh in its properties colors it with *Color by: Meshes*, also in the legend and the picture of the view; *Automatic* takes the color of its position again. *Constraints* (or C) in the results of *Hyperelastic block with a rigid plate* hides and shows the lines of the constraint and the control points.
- [ ] The light theme: the button left of *Solve* ▸ *Light* makes the app light at once, also another open tab of it, and a reload starts light without a dark flash; the view is white and its symbols are darker (e.g. the selected object in dark yellow); *Export ▸ Picture of the view* is a PNG on white; *System* follows the color scheme of the system; on the phone, the bar of the browser takes the color of the theme.
- [ ] Colors of sections and cell sets: in *Bushing with steel sleeves*, *Color* of the section `soft_body` (e.g. `#2b2d42`) colors the rubber with *Color by: Sections*, also in the legend and the picture of the view; *Automatic* takes the color of its position again; a project saved with it opens again with the color.
- [ ] Range of chosen sections: in the results of *Bushing with steel sleeves* (von Mises stress), *Range of* ▸ `soft_body` in the contour settings spreads the colors over the rubber, the sleeves above it take the extra color, *Min/Max* marks the extremes of the rubber and the scalar bar says *Range: soft_body*, also in the picture of the view; *All sections* takes the range of all again.
- [ ] A project of version 0.9 in version 0.8: a project with the color of a section, opened with `felupe-studio serve` of `felupe-studio[serve]==0.8.0`, says *This project uses the property `color` of `section.add`, which FElupe Studio 0.8.0 does not know*.
- [ ] The menus on the phone in portrait: *File*, *Help* and the theme menu of the header (*Dark*, *Light* and *System* with their hints), and the menu of an object in the browser, lie inside the window.
- [ ] The save dialog: in Chrome on the desktop, *Save project* of a sample opens the save dialog of the system with the name of the project (e.g. `glued-plate.felupe.zip`) and writes the file into the chosen folder; a name chosen there is the name of the project in the header, and a second *Save project* writes into the same file without asking; *Cancel* saves nothing. *File ▸ Export ▸ Python script* and *CSV* of the curve ask the same way, in the folder of the last export. - [ ] Steps that switch boundaries: in *Hyperelastic block with a rigid plate*, a step `release` without a ramp, whose *Boundaries* are all but `shift`, after `shift_and_tilt` in the job: the browser shows *no ramp · off: shift*; with `release` selected, the viewport fades `shift` and says *Off in release (faded): shift* below the view; the job has the note that its curve is off in `release`. ### Local checks

- [ ] MCP server (CPython): `pip install -e ".[mcp]"` in a clone, and the wheel: `python -m build`, then `tests/check_wheel.py` with the Python of a fresh environment, from another folder (CI does both); `felupe-studio-mcp --help`; added to an agent (e.g. `claude mcp add felupe-studio -- felupe-studio-mcp`), it opens a sample, solves it and saves the project, which opens in the app.
- [ ] Local runtime: `pip install "felupe-studio[serve]"` from the wheel (or `-e ".[serve]"` and `npm run build` in a clone), `felupe-studio serve` opens the app with *local Python* in the status bar; a sample with a mesh script shows the script first, solves and shows results; *Cancel* of a running job starts a new process; *About* lists the local versions.
- [ ] Agent bridge: `felupe-studio serve --agent` (with `[serve,mcp]`) prints the command for Claude Code; added, and *Help ▸ Connect an agent* in the tab (*Agent connected*), the agent opens a sample, changes a value and solves with live results; its changes are in the history and undo; a mesh script of the agent asks first (*Show the script*, *Run it*); *Disconnect* ends it. A second tab that connects replaces the first.
- [ ] PARDISO: `pip install "felupe-studio[serve,pardiso]"` on x86-64; *About* lists pypardiso; a job with *Linear solver* *PARDISO (local Python)* solves with the curve of SuperLU. In the browser the same job is an issue (*PARDISO needs Python on your computer*). `benchmark(n, solver="pardiso")` of `felupe_studio.benchmark` runs.
- [ ] A fixed token: with `FELUPE_STUDIO_TOKEN` set, two starts of `felupe-studio serve` print the same link.
- [ ] Other samples: `SAMPLES_DIR=<folder> npm run build` (and `npm run dev`) with a folder of two samples, one of them without `sample.json` and `thumbnail.svg`, shows only them (the second with its title from the id and the placeholder); they open and solve.
- [ ] Screenshots: `python docs/make_screenshots.py` (with the real Pyodide; `--pyodide <folder>` if the CDN is not reachable) makes the images of the guide and the README of this version, among them those of the light theme, the cut (`cut.png`) and the stacked profile (`stack.png`) and, with Pillow, `phone.png`, and with `[serve,mcp]` also `agent.png`.

### The release

- [ ] Tag `main`: `git tag -a vX.Y.Z -m "FElupe Studio X.Y.Z"` and `git push origin vX.Y.Z`.
- [ ] The workflow *Release* of the tag passes: the tag is the version, the wheel (with the built app) works outside of a clone, also `felupe-studio serve`, and the package is on PyPI (`pip install "felupe-studio[mcp,serve]==X.Y.Z"` in a fresh environment).
- [ ] GitHub release of the tag with the section of `CHANGELOG.md` as notes and the link to the app.
- [ ] The example brand from the tag, as a brand deploys it ([your own deployment](deployment.md)): a repository with `brands/example` as `brand/` and `brands/github-actions.yml` (or `gitlab-ci.yml`) of the tag builds the release `X.Y.Z` and deploys it to its Pages. The page has the name, the logo and the two samples of the brand, it starts in the light theme of the brand (`defaults.theme`) with a darker shade of its orange accent, *Help ▸ About* says *Based on FElupe Studio X.Y.Z*, and with its self-hosted Pyodide a sample solves without a request to `cdn.jsdelivr.net` (the network tab of the browser). A tag of that repository keeps the wheel of the brand as a file: installed from it with `[serve]`, `felupe-studio serve` shows the app and the samples of the brand.
- [ ] Set the date of the version in `CHANGELOG.md` (if it was not set before) and close the release issue.
